## 1. 規約・ポリシー調査結果

### API Gateway HTTP API の CORS サポート

| 項目 | 調査結果 |
|------|---------|
| HTTP API の CORS ネイティブサポート | ✅ 対応。`corsPreflight` 設定で OPTIONS プリフライトレスポンスを API Gateway が自動処理。Lambda を呼び出さない |
| REST API（v1）との違い | REST API は Lambda 側で CORS ヘッダーを手動付与が必要。HTTP API（v2）は API Gateway が自動付与 |
| `Access-Control-Max-Age` | `maxAge` パラメータで設定可能。1日（86400秒）設定でブラウザのプリフライトキャッシュが効く |
| `allowOrigins: ['*']` のリスク | PoC では許容。本番では特定ドメインに制限すること。ワイルドカードと `allowCredentials: true` は併用不可 |

出典: [AWS CDK API Reference - HttpApi corsPreflight](https://docs.aws.amazon.com/cdk/api/v2/docs/aws-cdk-lib.aws_apigatewayv2.CorsPreflightOptions.html)

---

### CloudFront OAC（Origin Access Control）

| 項目 | 調査結果 |
|------|---------|
| OAC vs OAI | OAI（旧方式）は非推奨。CDK v2.144+ では `S3BucketOrigin.withOriginAccessControl()` が推奨 |
| CDK での OAC 設定方法 | `cloudfrontOrigins.S3BucketOrigin.withOriginAccessControl(bucket)` で S3 バケットポリシーも自動生成 |
| SPA の 404 → index.html 対応 | `errorResponses` に `{httpStatus: 403, responseHttpStatus: 200, responsePagePath: '/index.html'}` と `{httpStatus: 404, ...}` の両方が必要（S3 は OAC で 403 を返す場合がある） |

出典: [AWS CDK CloudFront Origins - S3BucketOrigin](https://docs.aws.amazon.com/cdk/api/v2/docs/aws-cdk-lib.aws_cloudfront_origins.S3BucketOrigin.html)

### Lambda コンテナイメージと VOICEVOX Engine ライセンス

| 項目 | 調査結果 |

## 2. 追加ヒアリング事項

### 🔴 優先度：高（フェーズ0 PoC 開始前に必須）

- **iOS版 API Gateway エンドポイント URL と API キーの共有**
  - 質問: 現在 iOS版で使用している API Gateway の HTTP エンドポイント URL（`https://xxxxxx.execute-api.ap-northeast-1.amazonaws.com`）と `x-api-key` の値を共有いただけますか？
  - なぜ重要: CORS `allowOrigins` にブラウザのオリジンを追加する CDK 変更を行うため、既存スタックへのアクセスが必要です。

- **CDK スタックのリポジトリへのアクセス権限**
  - 質問: iOS版インフラの CDK コードが管理されている Git リポジトリへのアクセス権（read権限）をいただけますか？
  - なぜ重要: 既存スタック定義を確認してから CORS 追加の差分実装を行うためです。

- **ずんだもんキャラクター Web版利用規約の確認**
  - 質問: Web ブラウザで公開するアプリケーションにずんだもん音声を使用することについて、キャラクター利用規約（VOICEVOXキャラクター利用ガイドライン）の確認・同意は完了していますか？
  - なぜ重要: Web 公開前に必須の確認事項です。iOS版アプリストア配信と Web 公開では利用形態が異なるため、改めて確認が必要です。

### 🟡 優先度：中（フェーズ1 開始前に確認）

- **本番ドメイン名の確定**
  - 質問: Web版アプリの本番ドメイン（例: `englishlearn.example.com`）は確定していますか？Route 53 と ACM 証明書（us-east-1 リージョン）の準備が必要です。
  - なぜ重要: CloudFront カスタムドメインの設定と CORS `allowOrigins` の本番値設定に必要です。

- **iOS版と Web版の Lambda レートリミット共有方針**
  - 質問: API Gateway のスロットリング設定（デフォルト 10,000 RPS）は iOS版・Web版で共有されます。Web版追加後に iOS版のレスポンス速度への影響を懸念する場合、スタックを分離しますか？
  - なぜ重要: 個人利用規模では問題ありませんが、スケール時に考慮が必要です。

- **GitHub Actions の AWS 認証方式**
  - 質問: 現在の CI/CD（GitHub Actions）の AWS 認証は IAM ユーザーのアクセスキーですか、OIDC（GitHub → AWS AssumeRole）ですか？
  - なぜ重要: OIDC 方式の場合、S3 デプロイと CloudFront Invalidation のための IAM ロールポリシー追加が必要です。

### 🟢 優先度：低（フェーズ2 以降でも可）

- **S3 バケット名のプレフィックス命名規則**
  - 質問: S3 バケット名のプレフィックスや命名規則（例: `プロジェクト名-env-用途`）はありますか？
  - なぜ重要: CDK で S3 バケット名を明示的に指定する場合に必要です（指定なしの場合は CDK が自動生成）。

- **CloudWatch ログ保持期間**
  - 質問: Lambda の CloudWatch Logs の保持期間は現在何日に設定されていますか？Web版用の追加ログも同じ設定にしますか？
  - なぜ重要: ログ保持コストとデバッグのバランスに関わります（デフォルト: 無期限）。

## 3. 調査サマリーと推奨アクション

インフラ面の主要リスクは以下の 3 点です。

**CORS 設定の先行検証**: `allowOrigins` に本番ドメインを指定する前に、poc 環境で `['*']` で動作確認を実施すること。その後 dev/pro 環境では特定ドメインのみに制限する。Playwright E2E テストで OPTIONS プリフライトと実リクエストの両方を自動検証する。

**CloudFront SPA ルーティング（404/403 → index.html）**: S3 + OAC 構成では、存在しないパスへのアクセスが S3 から 403 Forbidden として返る場合がある。`errorResponses` に 403 と 404 の両方を設定することが重要。CDK unit test でこの設定を自動検証すること。

**Lambda コールドスタート**: VOICEVOX Engine は起動時間が長い（10〜30秒）。Web版ではブラウザのローディング UI（スピナー）と IndexedDB 音声キャッシュでユーザー体験を補完する。Lambda Provisioned Concurrency は月 ¥52,000 以上のコストが発生するため、個人利用規模では不要と判断。
