# 要件不明点調査・ヒアリング整理スキル

設計書や要件書を受け取り、**規約・ポリシーの調査**と**顧客への追加ヒアリング事項の整理**を行うスキルです。

---

## 実行手順

### ステップ1: 不明点・リスク箇所の抽出

入力された設計書・要件書を読み込み、以下のカテゴリで調査が必要な箇所をリストアップします:

- **外部サービス規約**: 利用しようとしているSaaS・プラットフォームの利用規約上のリスク（自動操作禁止、APIレート制限、データ取り扱いポリシー等）
- **API・技術制約**: 公式APIの有無・制限・認証方式・コスト
- **セキュリティ・コンプライアンス**: データ保持・プライバシー・業界規制
- **顧客側の未確定事項**: 回答が得られていない前提条件・要件の曖昧な箇所

### ステップ2: Web検索による規約・ポリシー調査

各外部サービスについて WebSearch を使って公式情報を調べます。

**調査の優先順位**:
1. 利用規約・禁止事項（自動操作・スクレイピングの可否は特に重要）
2. 公式APIの提供状況・ドキュメント
3. 料金・レート制限
4. データプライバシー・利用制限

**検索のコツ**:
- `site:` 指定で公式ページを優先（例: `site:〇〇.com 利用規約`）
- 英語でも並行検索（例: `〇〇 API terms of service automation`）
- 規約ページが見つかったら WebFetch で実際の内容を確認する
- 「見つからない」「不明」は正直に記載する。推測で書かない

### ステップ3: レポート生成

調査結果と追加ヒアリング事項を1つのMarkdownファイルにまとめます。

---

## 出力ファイル: `investigation-report.md`

以下のテンプレートに沿って生成してください:

```markdown
# 不明点調査レポート — [プロジェクト名]

**調査日**: YYYY-MM-DD
**調査対象**: [設計書・要件書のファイル名]

---

## 1. 規約・ポリシー調査結果

### [サービス名1]（例: 〇〇）

| 項目 | 調査結果 | 出典URL |
|------|---------|---------|
| 自動操作・スクレイピングの可否 | ✅ 許可 / ❌ 禁止 / ⚠️ 要確認 | URL |
| 公式API提供 | あり（[URL]）/ なし | URL |
| APIレート制限 | 〇〇 req/min など / 不明 | URL |
| データ利用制限 | ... | URL |

**調査まとめ**: [2〜3文でリスク・注意点を要約]

### [サービス名2]
...

---

## 2. 追加ヒアリング事項

顧客への確認が必要な項目を優先度順に並べます。

### 🔴 優先度：高（着手前に必須）

- **[項目名]**
  - 質問: ...
  - なぜ重要: ...

### 🟡 優先度：中（フェーズ1開始前に確認）

- **[項目名]**
  - 質問: ...

### 🟢 優先度：低（フェーズ2以降でも可）

- **[項目名]**
  - 質問: ...

---

## 3. 調査サマリーと推奨アクション

[全体の調査結果を踏まえた、次のアクションへの提言を3〜5文で]

**次のステップ**:
- [ ] [具体的なアクション1]
- [ ] [具体的なアクション2]
```

---

## 品質チェックリスト

出力前に確認:

- [ ] 調査結果に「推測」「おそらく」ではなく、実際にWebで確認した内容が書かれている
- [ ] 見つからなかった情報は「不明（公式ページ未確認）」と正直に記載している
- [ ] ヒアリング事項に「なぜ重要か」が添えられている
- [ ] 優先度の高い項目が先頭にある
- [ ] 出典URLが記載されている（見つかった場合）

## 出力場所

`investigation-report.md` をワークスペースフォルダに保存すること。
