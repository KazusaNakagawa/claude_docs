### Web Speech API（`webkitSpeechRecognition`）

| 項目 | 調査結果 | 出典URL |
|------|---------|---------|
| ブラウザ対応状況 | ⚠️ Chrome / Edge: 対応。Firefox: 非対応。Safari: 部分的サポート（iOS 14.5+で SpeechRecognition 対応だが制限あり） | https://caniuse.com/speech-recognition |
| サーバー処理 | ⚠️ Chrome の実装は Google サーバーで処理。音声データが Google に送信される | https://wicg.github.io/speech-api/ |
| 商用利用 | ⚠️ Google の利用規約に準拠。大量リクエストは制限される可能性あり | https://policies.google.com/terms |
| オフライン対応 | ❌ 非対応（ネットワーク必須） | https://developer.chrome.com/docs/capabilities/web-apis/web-speech-api |
| レート制限 | ⚠️ 不明（Chrome の実装依存）。短時間の連続録音で制限が発生する可能性あり | - |
| プライバシー | ⚠️ Chrome で使用時、音声データは Google サーバーに送信されます。ユーザーへの明示が必要 | https://wicg.github.io/speech-api/ |

**調査まとめ**: Web Speech API は Chrome/Edge のみ安定して利用可能。Safari の実装は制限が多く、実用的な発音チェック機能には不向き。音声データが Google サーバーに送信される点はプライバシーポリシーへの記載が必要。将来的に完全なブラウザ対応が必要な場合は、DeepGram API や OpenAI Whisper API への移行を検討すること。

## 2. 追加ヒアリング事項

### 🔴 優先度：高（フェーズ0開始前に必須）

- **Safari ユーザーへの対応方針**
  - 質問: Safari ユーザー（特に iPhone の Safari）は発音チェック機能が利用できません。Safari 対応は必要ですか？（対応する場合は OpenAI Whisper API 等の代替手段で +5〜10人日の追加開発が必要です）
  - なぜ重要: Safari ユーザー向けのフォールバック設計が決まらないと、フロントエンドの発音チェック UI の実装方針が定まりません。

- **ずんだもん商用利用規約の確認・同意**
  - 質問: VOICEVOX ずんだもん音声をWebサービスに組み込む場合のキャラクター利用規約は確認・同意済みですか？
  - なぜ重要: iOS版と同様、Web版でも商用利用前に確認が必要です。

- **iOS版との並行運用・データ共有**
  - 質問: Web版と iOS版を並行して運用しますか？同一アカウントで両版のデータを共有（クラウド同期）しますか？
  - なぜ重要: iOS版から Web版へのデータ移行 API（JSON インポート互換）の優先度と設計に影響します。

### 🟡 優先度：中（フェーズ1開始前に確認）

- **ログイン方式（Google/GitHub SSO の要否）**
  - 質問: メール/パスワード認証のみで十分ですか？Google や GitHub でのソーシャルログインは必要ですか？
  - なぜ重要: SSO を追加する場合、Cognito のフェデレーション設定が必要で +2〜3人日の追加工数が発生します。

- **音声データのプライバシーポリシー**
  - 質問: Web Speech API 利用時に音声データが Google サーバーに送信されますが、プライバシーポリシーへの記載内容と方針を確認させてください
  - なぜ重要: 個人情報保護法・GDPR 対応の観点から、音声データの取り扱いを明示する必要があります。

- **FastAPI の実行環境（Lambda vs ECS Fargate）**
  - 質問: バックエンド（FastAPI）は Lambda（コールドスタートあり）と ECS Fargate（常時起動・固定コスト）のどちらを希望しますか？
  - なぜ重要: Lambda はコスト安（使った分だけ）ですが初回レスポンスに 1〜3 秒の遅延があります。ECS Fargate は常時起動で遅延なしですが月額固定費（約 ¥5,000〜10,000/月）が発生します。

### 🟢 優先度：低（フェーズ2以降でも可）

- **Progressive Web App（PWA）対応**
  - 質問: スマートフォンのホーム画面に「アプリとして」追加できる PWA 対応は必要ですか？
  - なぜ重要: PWA 対応（Service Worker + Manifest）は +3〜5人日の追加工数です。オフラインキャッシュも含む場合はさらに追加工数が必要です。

- **iOS版 → Web版のデータ移行ガイド**
  - 質問: 既存 iOS版ユーザーが Web版に移行するためのガイド（JSON エクスポート → インポート手順書）をドキュメントとして準備しますか？

## 3. 調査サマリーと推奨アクション

Web版固有の最大リスクは **Web Speech API の Safari 非対応** です。iPhone ユーザーが Safari を使う場合、発音チェック機能が利用できないため、Chrome への誘導バナーか代替音声認識 API（OpenAI Whisper / DeepGram）の検討をフェーズ0 で確定させる必要があります。音声データの Google サーバー送信については、プライバシーポリシーへの記載が法的要件となります。Cognito は 50,000 MAU まで無料で使えるため、MVP 段階では追加コストなく認証基盤を構築できます。
