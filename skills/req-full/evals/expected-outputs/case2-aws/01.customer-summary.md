# 要件確認・対応方針 — VOICEVOX TTS インフラ (AWS CDK) — Web版対応

**作成日**: 2026-03-20
**参考**: iOS版設計書（case1/aws）をベースに Web クライアント対応へ更新

---

## 対応可否
**対応可能**

iOS版の VOICEVOX Lambda インフラをベースに、Web ブラウザ（React）からの呼び出しに対応するための CORS 設定・API 認証の追加が主な変更となります。インフラ構成は iOS版とほぼ同一のため、追加工数は最小限です。

---

## iOS版インフラからの主な変更点

| 項目 | iOS版（case1/aws） | Web版（本案） |
|------|-----------------|------------|
| CORS 設定 | iOS アプリ（HTTP クライアント）はブラウザではないため CORS 不要 | **React SPA のドメインを CORS 許可リストに追加が必須** |
| クライアント | iOS ネイティブ App | ブラウザ（Chrome / Edge） |
| 認証 | API Key（PoC なし → dev/pro で必要） | API Key 継続（Cognito での Bearer Token 認証は FastAPI バックエンドが担当） |
| プリフライトリクエスト | 不要 | **OPTIONS メソッドのプリフライトレスポンスを返す設定が必要** |
| ドメイン管理 | 不要 | React SPA のデプロイドメインを CORS に登録 |

---

## 提案する進め方

iOS版のフェーズ1（CDK 整備・CI/CD）完了後、以下の追加対応が必要です：

| 追加タスク | 内容 | 追加工数 |
|-----------|------|---------|
| CORS 設定更新 | React SPA ドメイン（dev/pro）を CORS 許可に追加 | 0.5人日 |
| プリフライト対応確認 | OPTIONS リクエストへの正常応答テスト | 0.5人日 |
| ブラウザ統合テスト | Chrome/Edge から fetch API での呼び出し確認 | 1人日 |
| **合計追加工数** | | **2人日** |

iOS版インフラと Web版インフラは**同一スタック（CDK）で管理**できるため、別リポジトリへの分離は不要です。

## 確認させてください（不明点・前提条件）

- **React SPA のデプロイドメイン**: Web版 React アプリの本番ドメイン（例: `https://app.example.com`）はすでに確定していますか？CORS 設定に必要です
- **iOS版との共存**: iOS版と Web版で同一の VOICEVOX Lambda を共有しますか？それとも環境を分けますか？（共有推奨 — コスト削減）
- **ブラウザキャッシュ戦略**: iOS版は FileManager でキャッシュ、Web版は IndexedDB でキャッシュしますが、将来的に S3 サーバーキャッシュに統一しますか？

---

## リスク・注意点

- **CORS 設定漏れ**: 本番デプロイ後に CORS エラーで VOICEVOX TTS が動作しない問題が頻発します。dev 環境でのブラウザ統合テストを必ず実施してください
- **iOS版と Web版の CORS 差分管理**: iOS版（CORS 不要）と Web版（CORS 必要）を同一 CDK スタックで管理する場合、環境変数でクライアント種別を管理する設計が必要です
