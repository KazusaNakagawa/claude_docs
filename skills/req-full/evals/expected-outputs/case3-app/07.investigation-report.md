## 1. 規約・ポリシー調査結果

### Web Speech API ブラウザ対応状況

| 項目 | 調査結果 | 出典URL |
|------|---------|---------|
| SpeechRecognition (STT) Chrome | ✅ 完全対応（Chrome 33+、Edge）| https://caniuse.com/speech-recognition |
| SpeechRecognition (STT) Safari | ⚠️ Safari 14.1以降で部分対応。Apple サーバーへの音声送信が発生し、「音声認識へのアクセス」許可モーダルが表示される | https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API |
| SpeechRecognition (STT) Firefox | ❌ 未対応 | https://caniuse.com/speech-recognition |
| SpeechSynthesis (TTS) Safari | ✅ Safari 7.1以降で完全対応。VOICEVOX のフォールバックとして利用可能 | https://www.testmuai.com/web-technologies/speech-synthesis-safari/ |
| SpeechSynthesis (TTS) Chrome/Edge | ✅ 完全対応 | |

**調査まとめ**: STT（音声認識）は Chrome/Edge での利用を推奨。Safari は部分対応だが Apple のサーバー経由になる点を考慮すること。TTS フォールバック（Web Speech Synthesis）は Safari を含む主要ブラウザで対応済み。発音チェック機能のみ「Chrome/Edge 推奨」の案内 UI が必要。

### OpenAI API 利用規約（ブラウザ直接呼び出し）

| 項目 | 調査結果 | 出典URL |
|------|---------|---------|
| ブラウザからの直接 API 呼び出し | ✅ 技術的制限なし。個人・開発者は OpenAI Services Agreement に基づき API を利用できる | https://openai.com/policies/services-agreement/ |
| APIキー管理責任 | ⚠️ API キーの売買・共有は禁止。localStorage に保存する場合、ユーザー自身が管理責任を持つことを明示すること | https://openai.com/policies/usage-policies/ |
| 競合 AI モデル開発への利用禁止 | ⚠️ Output を競合 AI モデルの開発に使うことは禁止。例文生成のみへの利用は問題なし | https://openai.com/policies/services-agreement/ |
| 2025年5月更新版 | ✅ 2025年5月31日発効の最新 Services Agreement が現行。内容変更点: 利用禁止事項の整理・明確化 | https://community.openai.com/t/new-openai-services-agreement-effective-may-31-2025/1249405 |

**調査まとめ**: 個人利用アプリのブラウザから OpenAI API を直接呼び出す構成は規約上問題なし。ただし API キーは localStorage に平文保存のため DevTools で確認可能。設定画面にて「API キーは外部に共有しないでください」の注意書きを表示すること。

### IndexedDB ストレージ容量制限

| ブラウザ | 上限 | 備考 |
|---------|------|------|
| Chrome/Edge | ディスク空き容量の最大 60% | 通常数十〜数百 GB。実用上の問題はほぼない |
| Firefox | 10% of disk または 10GB（best-effort mode） | 永続ストレージ許可で最大 50% |
| Safari | ブラウザによって異なる（概ね数百 MB〜） | プライベートブラウジングは制限あり |

**調査まとめ**: デスクトップブラウザでは実用的な上限（数十 GB 以上）であり、音声キャッシュ 100MB 上限でも問題なし。ただし Safari プライベートブラウジングは容量が制限される場合があるため、キャッシュ容量超過時のエラーハンドリングを実装すること。

出典: [MDN - Storage quotas and eviction criteria](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

## 2. 追加ヒアリング事項

### 🔴 優先度：高（フェーズ0開始前に必須）

- **VOICEVOX Lambda エンドポイント URL と API キーの共有**
  - 質問: iOS版で使用している API Gateway エンドポイント URL と x-api-key を共有いただけますか？
  - なぜ重要: CORS 設定追加のためにエンドポイント情報が必要です。フェーズ0の PoC で最初に検証します。

- **ずんだもんキャラクター利用規約の確認**
  - 質問: Web 版でも VOICEVOX ずんだもん音声をサービスに組み込む場合のキャラクター利用規約（商用利用条件）の確認・同意は完了していますか？
  - なぜ重要: iOS版・Web版ともに同じキャラクター規約の確認が必要です。Web 公開前に必須です。

- **iOS版 Lambda と Web版での API キー共用・分離方針**
  - 質問: iOS版と Web版で同一の API Gateway エンドポイント・API キーを共用しますか？
  - なぜ重要: 共用する場合は CORS 設定追加のみで済みます（+0.5人日）。分離する場合は別スタックが必要（+5人日）。

### 🟡 優先度：中（フェーズ1開始前に確認）

- **Web版ドメイン名の確定**
  - 質問: Web版のドメイン名（例: `englishlearn.example.com`）は決まっていますか？Route 53 と ACM 証明書の準備が必要です。
  - なぜ重要: CORS の許可オリジン設定に本番ドメインが必要なため、フェーズ1開始前に確定が必要です。

- **Safari ユーザー向け発音チェック機能の対応方針**
  - 質問: Safari ユーザーに対して、発音チェック機能は「Chrome/Edge を使ってください」と案内しますか？それとも発音チェックボタン自体を非表示にしますか？
  - なぜ重要: UI の実装方針が変わります。

- **OpenAI API キーのセキュリティ方針**
  - 質問: API キーを localStorage に保存する方式（現設計）で問題ありませんか？より安全なバックエンド経由方式（FastAPI BFF）も選択肢としてあります。
  - なぜ重要: 個人利用想定であれば現設計で問題ないですが、複数ユーザーへの展開を想定する場合はバックエンド代理呼び出しを検討する必要があります。

### 🟢 優先度：低（フェーズ2以降でも可）

- **iOS版とのデータ同期要件**
  - 質問: iOS版と Web版でのデータ同期（同じ単語リストを使いたい）は必要ですか？
  - なぜ重要: 不要であれば IndexedDB のみの設計で完結します。必要な場合は RDS + FastAPI バックエンドへの移行が必要になります（+30人日）。

- **Lambda コールドスタート（最大30秒）のUX 許容範囲**
  - 質問: ブラウザで初回音声生成に最大30秒かかる場合、許容できますか？
  - なぜ重要: 許容できない場合は Provisioned Concurrency（+¥52,000/月）の導入を検討してください。

## 3. 調査サマリーと推奨アクション

Web版固有の主要課題は以下の3点です。

**STT ブラウザ依存**: Web Speech Recognition は Chrome/Edge のみ完全動作。Safari ユーザー向けには「Chrome/Edge をご利用ください」の案内 UI を実装する。TTS フォールバック（SpeechSynthesis）は Safari でも動作するため、発音チェック以外の機能は全ブラウザで利用可能。

**OpenAI API キー管理**: ブラウザの localStorage に保存するため DevTools から確認できる。個人利用前提で許容範囲だが、設定画面に注意書きを表示すること。

**VOICEVOX キャラクター利用規約**: ずんだもんキャラクターの Web 版利用規約はお客様側での確認が必須。確認が取れるまでキャラクター名・画像の使用は保留。

- [ ] VOICEVOX Lambda エンドポイント URL と API キーの共有（担当: お客様）
- [ ] ずんだもんキャラクター利用規約の確認・同意（担当: お客様）
- [ ] iOS版 Lambda との共用・分離方針の確定
- [ ] 本番ドメイン（CloudFront カスタムドメイン）の確定
- [ ] Safari ユーザー向け発音チェック機能の対応方針確認
