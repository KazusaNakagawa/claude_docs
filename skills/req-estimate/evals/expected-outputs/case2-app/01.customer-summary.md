# 要件確認・対応方針 — EnglishLearnApp Web版

**作成日**: 2026-03-20
**参考**: iOS版設計書（case1/app）をベースにWeb版へ移植・再設計

---

## 対応可否
**対応可能**

iOS版（SwiftUI）と異なり、Web版は弊社標準スタック（React + TypeScript / Python FastAPI / AWS）で**完全に対応可能**です。iOS専門エンジニアは不要となり、スタック統一によりチーム構成・採用・保守が容易になります。また、ブラウザで動作するためインストール不要で複数デバイス（PC・スマートフォン）から利用できます。

---

## ご要件の理解（Web版への読み替え）

| iOS版の機能 | Web版での実現方法 |
|-----------|---------------|
| SwiftUI ネイティブ UI | React + TypeScript（SPA、CloudFront + S3 でホスティング） |
| AVSpeechSynthesizer（ネイティブ TTS） | Web Speech API（ブラウザ内蔵 TTS）または VOICEVOX Lambda |
| SFSpeechRecognizer（発音チェック） | Web Speech API（`webkitSpeechRecognition`）— Chrome 必須 |
| iOS Keychain（API キー保管） | AWS Secrets Manager / バックエンド経由（クライアントに秘密情報を持たせない） |
| FileManager + JSON（ローカルストレージ） | PostgreSQL（RDS）クラウド保存 → 複数デバイス間で自動同期 |
| AVQueuePlayer（連続再生） | HTML5 Audio API + Web Audio API |
| ロック画面連携（MediaPlayer framework） | Media Session API（Chrome/Edge でサポート）|
| JSON エクスポート/インポート | ダウンロード URL / ファイルアップロード API |
| アプリ内設定（UserDefaults） | バックエンド DB に保存（ログイン状態で設定が引き継がれる） |

## 確認させてください（不明点・前提条件）

- **対象ブラウザ**: 発音チェック（Web Speech API）は現時点で Chrome / Edge のみ対応です。Safari や Firefox ユーザーへの対応方針を教えてください
- **認証方式**: メール/パスワード認証のみでよいですか？Google / GitHub でのソーシャルログインは必要ですか？
- **iOS アプリとの共存**: Web版と iOS版を並行運用しますか？データを共有（クラウド同期）しますか？
- **モバイルブラウザ対応**: スマートフォンのブラウザからも使えるようにしますか？（レスポンシブ対応の有無）
- **OpenAI API キーの管理**: Web版ではクライアントに API キーを持たせず、バックエンド経由で OpenAI を呼び出す設計を推奨します。ユーザーごとに個別の API キーを使いたいですか、それともサービス共通の API キーで管理しますか？

## iOS版と比較したリスク・注意点

- **Web Speech API の制限**: Chrome / Edge のみ対応。Safari は現時点で非対応のため、発音チェック機能のブラウザ対応範囲が限定されます
- **Web Speech API のオフライン非対応**: iOS版の SFSpeechRecognizer と同様、サーバー処理のためインターネット接続必須です
- **バックエンドの追加開発**: iOS版はデバイスローカル保存でしたが、Web版ではクラウド DB + バックエンド API が必須となるため、その分の開発工数が増加します
- **VOICEVOX のコールドスタート**: iOS版と同様に Lambda の初回起動に 10〜30 秒かかります
